# 03 分阶段开发与验证门禁

P3–P7 五道门。**每道门的判据是「证据」，不是「我觉得差不多了」。** 每条结论后面必须跟证据路径（截图/日志/命令输出），没有证据就写 `NOT_RUN`。

状态只用三个词：`PASS` / `FAIL` / `NOT_RUN`。**不许写「基本通过」「应该没问题」「已验证（其实是浏览器里点了一下）」。**

## 环境分层（报告里必须分开写）

| 层 | 含义 | 能证明什么 |
|---|---|---|
| `浏览器` | 本地 Chrome 直接打开 index.html | 只能证明逻辑/布局大致对，**不能证明容器可用** |
| `模拟器` | `redapp dev --dir ./dist` 官方模拟器 | 能证明容器能加载、`window.xhs` 存在、部分能力可调 |
| `真机` | 手机小红书 App 扫码预览 | **只有这层能写「平台功能 PASS」** |

复刻/开发阶段用浏览器迭代没问题，但**报告里不许把浏览器结果记成真机 PASS**。

---

## P3 骨架：先让它能跑起来

**目标**：一个能启动、有安全区、能读写存储、SDK 缺失也不崩的空壳。

任务：
1. 复制 `templates/stable-app` 或 `templates/vite-app` 到 `src/`。
2. 改 `index.html` 标题、`app.js` 里的应用名。
3. 确认外置 JS 加载顺序、无内联脚本。
4. 跑一次 `node scripts/preflight.js --dir ./dist`（此时应该只剩「玩法未实现」类的 FAIL，不该有结构类 FAIL）。

验证项（全部在浏览器 + 模拟器两层各做一次）：

- [ ] 页面能打开，无 console 报错
- [ ] 顶部内容不被状态栏压住，底部按钮在 Home 指示条之上（用 `getWindowInfo()` 驱动，不是只靠 `env()`）
- [ ] 320 宽和 430 宽下都没有横向滚动、没有元素溢出
- [ ] 存储：写一次、刷新后还读得到；Storage 不可用时退回内存且界面不崩
- [ ] 模拟器里 `window.xhs.miniTool` 存在，能力检测结果打印出来符合预期
- [ ] 拔掉 SDK（浏览器直接开）时，页面照样能进下一屏

证据：`docs/P3_报告.md` + 2 张截图（320/430）+ 模拟器启动日志。

**退出条件**：空壳能进、能退、不崩、安全区正确。别急着写玩法。

---

## P4 核心玩法：先逻辑，后表现

**目标**：玩法规则可玩、可测、可复现。

任务：
1. 按《玩法规则》写纯逻辑层（不碰 DOM/Canvas）。零构建模板放 `core.js`，TS 模板放 `src/core/`。
2. 逻辑层暴露：`create(seed)`、`input(action)`、`tick(dt)`、`snapshot()`。
3. 渲染层只读 `snapshot()` 画图，**不许在渲染层改状态**。
4. 写一个能在 Node 里跑的测试（`node tools/test-core.mjs` 或 `vitest`），覆盖：正常一局、边界输入、结束判定、分数公式。

验证项：

- [ ] 同一个 seed 跑两次，结果完全一致（确定性）
- [ ] 单局从开始到结算，状态机没有非法转移（`ready→result` 这种要拦住）
- [ ] 快速连点 20 次不会重复结算、不会多加分
- [ ] 切后台再回来，逻辑不跳帧（传 `dt` 上限，别用真实时间差硬算）
- [ ] 三条难度档位的手感差异能被描述出来（快到什么程度）
- [ ] 逻辑测试全绿，输出贴进报告

证据：`docs/P4_报告.md` + 测试输出 + 一段 15 秒的游玩录屏（浏览器即可）。

**退出条件**：能玩一整局，输赢判定和分数都对，逻辑测试过。

---

## P5 界面 / 中文 / 音频

**目标**：能看、能懂、有反馈。

任务：
1. 按《界面与文案》把每一屏做出来（启动、玩法、暂停、结算、设置）。
2. 所有可见文案换成中文，去掉任何日文/英文残留。
3. 接音频：首次手势里解锁 AudioContext；音效按事件触发；静音开关生效并持久化。
4. 加触控反馈：按下态、命中反馈、失败震动（`vibrateShort` 有则用，无则忽略）。

验证项：

- [ ] 5 屏都有截图，320 / 390 / 430 三种宽度各一组
- [ ] 每个可点元素的触控区 ≥ 44×44（用 `getBoundingClientRect` 量，不靠目测）
- [ ] 没有文字溢出容器、没有文字重叠、没有被固定栏压住的内容
- [ ] 结算页信息完整：分数、最佳、评级、再玩一局、海报
- [ ] 音效在模拟器里能听到（真机待验要写 `NOT_RUN`）
- [ ] 关掉声音后游戏照常进行；AudioContext 创建失败不崩
- [ ] 手机竖屏下无横向滚动

证据：`docs/P5_报告.md` + 每屏截图路径 + 音频实测记录（模拟器/真机分开写）。

**退出条件**：一个没看过方案的人，不看说明也能玩明白。

---

## P6 平台能力与兼容

**目标**：平台能力接上且失败可降级；代码能进容器。

任务：
1. 按《平台能力》接：海报生成（Canvas → PNG dataURL）、保存相册、发笔记、关注、分享、存储。
2. 每个能力都走「三层判空 + try/catch + 明确状态」，状态区分 `SUCCESS/CANCELLED/UNSUPPORTED/FAILED/LIMIT_REACHED`。
3. 跑 `node scripts/preflight.js --dir ./dist --name "..." --slogan "..." --icon ... --cover ...`，把 FAIL 全修掉。
4. 兼容自查：ES2017 语法、CSS Chrome 61 回退、无外链、无 fetch/XHR。

验证项：

- [ ] 海报：生成的图是 3:4，1080×1440，内容完整不裁切
- [ ] 保存相册：用户拒绝授权 → 只提示，不假装成功
- [ ] 发笔记：文案不写「已发布」，只写「已打开编辑器」
- [ ] 关注：`follow_status` 为 -1 时不显示成功；20002/15404/10003 各有对应提示
- [ ] 分享：旧版本/半屏下入口隐藏，不报错
- [ ] 模拟器里每个能力至少调通一次，失败分支各造一次
- [ ] preflight 的兼容扫描 0 FAIL
- [ ] 无 SDK 环境完整可玩

证据：`docs/P6_报告.md` + 能力矩阵表（能力 × 浏览器/模拟器/真机 × PASS/FAIL/NOT_RUN）+ preflight 输出。

**退出条件**：能力矩阵没有空白格（要么 PASS，要么写清 NOT_RUN 及原因）。

## P7 素材与发布

**目标**：名字、简介、图标、封面、zip 全部合规，能上传送审。

任务与门禁：

1. 按 `04-branding.md` 出名字/简介/图标/封面，用户确认。
2. `node scripts/make-zip.js --dir ./dist --out "release/<名字>.zip"`。
3. `node scripts/preflight.js --zip "release/<名字>.zip" --icon ... --cover ... --name ... --slogan ... --version 1.0.0` → **必须全 PASS**。
4. 上传 → 预览二维码 → 用户扫码并明确「预览通过」→ 送审。全流程见 `05-release.md`。

验证项：

- [ ] 名字、简介都 ≤14 字符（脚本量，不是目测）
- [ ] 图标 512×512、1:1、≤5MiB、缩到 48px 还能认出
- [ ] 封面 1080×1440、3:4、≤10MiB、手机上标题看得清
- [ ] zip 根目录直接是 index.html，无 `__MACOSX`、无 `.map`、无 node_modules
- [ ] zip ≤10MiB（目标 ≤2MiB），解压总大小 ≤30MiB
- [ ] preflight 全 PASS，报告存 `docs/preflight.json`
- [ ] 上传返回的 fileId 与 md5 记在 `release/提交记录.md`
- [ ] 预览二维码已给用户看过，用户明确回复「预览通过」

**退出条件**：送审命令执行成功，状态为「审核中」，并把状态写进交付说明（**不写「已发布」**）。

---

## 最小路径（只做一部分时）

用户只要打包/送审时：

1. 直接跑 preflight，把 FAIL 逐条修掉（这一步经常暴露真问题）。
2. 缺图标/封面就补（`04-branding.md`）。
3. 打包 → 上传 → 预览 → 送审。
4. 报告里明确写：「本次只做 P7，P3–P6 未回归，历史验证状态见原项目 docs。」

**最小路径不等于跳过验证**：preflight 的每一条 FAIL 都必须修，不能「先传上去看看」。

## 回归规则

改动触碰以下任一内容，必须重跑对应门禁：

| 改动 | 要重跑 |
|---|---|
| 核心逻辑 `core` | P4 测试 + P5 截图（玩法屏） |
| 样式 / 布局 | P5 三宽度截图 + P6 preflight |
| 平台桥接 | P6 能力矩阵 |
| 资源/素材新增 | preflight + zip 体积 |
