# 01 引导对话：把想法问成能开发的规格

这一份是你和用户对话时最常翻的东西。目标只有一个：**聊完之后，你能直接写出《玩法规则》和《界面清单》，不再需要回头问「这里到底怎么算」**。

## 先判断用户在哪一步

接到任务先看用户手里有什么，四种入口走法不同：

| 入口 | 用户表现 | 走法 |
|---|---|---|
| **A 有想复刻的游戏** | 「我想做个跟 XX 一样的小游戏」并给了链接 | 先取证（下面「复刻分支」），再补完剩下的需求 |
| **B 只有模糊想法** | 「想做个解压小工具」「不知道做啥，你帮我出主意」 | 先给 3 个选题方向让他选，再进轮次对话 |
| **C 已经有方案** | 丢一堆文档/压缩包过来 | 只做缺口检查：按 `02-spec-package.md` 对照，缺哪份补哪份，别重写 |
| **D 只缺某一步** | 「帮我打包/改图标/送审」 | 跳过 P1–P2，走最小路径（见 SKILL.md 常见追问） |

## 开场白（第一句话就照这个来）

> 我可以直接帮你把想法做成能上架小红书的小工具，全程在这个对话里完成，你不用写代码。
> 先问一句：**你有没有特别想复刻的小游戏或小工具？** 有的话把链接发我，我照着它的玩法做一个（美术和素材会重新做，不搬原版资源）；没有也没关系，我们从玩法开始聊，大概十几分钟就能定下来。

**「有没有想复刻的」这个问题必须在第一轮问，不能省。** 用户说没有，立刻往下走，不要追问他为什么不复刻。

---

## 复刻分支：先取证，再谈玩法

### 第 1 步：自动尝试取证（不要一上来就要用户截图）

有浏览器/抓取能力时先自己试，能拿到多少算多少：

1. 打开链接，记录最终 URL、页面标题、可见版本号、"更新时间"。
2. 截图：首页、一局进行中、结算页、设置页。
3. 抓页面结构：DOM 层级、canvas 尺寸、按钮文案、资源清单（图片/音频/字体文件名）。
4. 玩一局（能玩的话），记操作方式、判定时机、失败条件、单局时长。
5. 把拿到的写进 `01_需求/原版取证.md`，每条后面标证据来源（截图路径 / DOM 片段 / 录屏时间点）。

### 第 2 步：拿不到就给取证清单

遇到**登录墙、只在 App 里能开、纯 canvas 抓不到内容、资源混淆加密、地区限制**——不要硬啃，也不要编。给用户这份清单，让他照着做（他不需要懂技术）：

> 这个链接我这边打不开完整内容（原因：需要登录 / 只能在 App 内打开）。麻烦你帮我做这几件事，做完我就能开始：
> 1. **首页截图**：打开游戏第一屏，整个屏幕截一张。
> 2. **完整一局录屏**：从点开始到结算，用手机录屏录一遍（不用剪）。
> 3. **结算页截图**：分数、评级、按钮都拍进去。
> 4. **设置页截图**：如果有音效/震动/语言开关。
> 5. **操作描述**：用手指怎么玩？点、拖、划、长按？大概多久一局？
> 6. **你最想保留的 3 个细节**：比如「连击加分的爽感」「失败时的碎碎念文案」「卡牌翻面的动画」。
> 7. （可选）**你不想要的**：原版哪里你觉得不好玩、想改掉的。
>
> 截图和录屏直接发在对话里就行。

### 第 3 步：证据分级，写进文档

| 等级 | 含义 | 允许的用法 |
|---|---|---|
| `VERIFIED` | 截图/录屏/实机里直接看到的 | 可以当规格写进《玩法规则》 |
| `PARTIAL` | 只看到一个片段或粗略数值 | 写进文档但标注「近似」 |
| `UNKNOWN` | 没证据 | **只能写进《风险与未知》**，不许猜一个数值顶上 |

**铁律：`UNKNOWN` 的数值不许出现在代码里当常量，除非用户明确拍板「就用这个」。** 拍板了就在决策表里记一笔，写清是推测。

### 第 4 步：划线——玩法可复刻，素材不复刻

开场就要说清楚（写进《风险与未知》）：

- 可以复刻：玩法机制、操作方式、界面布局思路、节奏手感。
- 不可以搬：原版角色形象、美术资源、logo、音乐音效文件、文案原文。
- 名字、图标、封面必须原创，不能让人一眼看出是原作。
- 如果原版有明显商标/角色，提醒用户「做成致敬可以，直接抄会被驳回」。

## 原创分支：三轮把玩法聊出来

用户没有复刻对象时，第一轮给 3 个候选方向（每个一句话 + 一句「为什么适合做成小工具」），让他选或说「都不喜欢，我想要 XXX」。选完进下面的轮次。

---

## 通用轮次表（每轮 3–5 题，问完立刻总结）

> 每轮结束给一段 3 行总结：「我记下来的是…… / 这里我先按 X 处理，你可以改 / 下一轮聊 Y」。**不要一次问完所有轮。**

### 第 1 轮：这是给谁玩的

| 问什么 | 选项（第一个是推荐） | 为什么问 |
|---|---|---|
| 谁玩？ | ① 刷到就随手玩的路人 ② 某个圈子的爱好者 ③ 我自己和朋友的圈子 | 决定难度和上手指引长度 |
| 一局多久？ | ① 30 秒–1 分钟 ② 1–3 分钟 ③ 3 分钟以上 | 超过 3 分钟要存档和暂停 |
| 玩完带走什么？ | ① 只想爽一下 ② 能生成一张成绩海报发笔记 ③ 要历史最佳/收集进度 | 决定 P6 要不要做海报和存储 |

默认值：路人 / 30 秒–1 分钟 / 成绩海报。这三条能覆盖 80% 的小工具。

### 第 2 轮：核心玩法一句话

要求用户用一句话说清「**玩家在做什么，什么时候输/赢**」。他说的可能是「就是点点点」，你要追问到能写成规则：

> 「点点点」有几种可能，你更接近哪种？
> ① 看到目标就点，点错了扣血（反应类）
> ② 连续点让数字变大，太大会炸（节奏类）
> ③ 点一下切换状态，凑成图案（解谜类）

然后逐项确认：

1. **操作**：点 / 拖 / 划 / 长按 / 双指？单手还是双手？
2. **一局怎么结束**：时间到 / 血条空 / 步数用完 / 主动结算？
3. **难度怎么涨**：越来越快 / 目标越来越多 / 空间越来越小？三个档位说清。
4. **什么算「玩得好」**：分数、连击、剩余时间、收集完成度？
5. **失败后可不可以立刻再开一局**（必须能，这是留存底线）。

写完回读一遍给用户：「我理解的是——你点掉从下面飘上来的泡泡，点错扣一颗心，三颗心掉光结束，泡泡越来越快。对吗？」**用户说「对」才算这轮过。**

### 第 3 轮：长什么样、有没有声音

| 问什么 | 选项 | 默认 |
|---|---|---|
| 画面风格 | ① 扁平插画 ② 像素/复古 ③ 极简几何 ④ 手绘涂鸦 | 扁平插画（最好做、最不容易崩） |
| 主色 | 从 3 个配色方案里选（直接给色值 + 一句感觉） | 高对比暖色 |
| 有没有声音 | ① 要音效，不要 BGM ② 都要 ③ 不要声音 | 要音效，不要 BGM（体积和合规都最稳） |
| 中文文案量 | ① 只按钮和结算 ② 有引导和提示 ③ 有剧情文字 | ① + 少量提示 |

**这里必须提前告诉用户平台限制**（别等他提了「我要背景音乐」才说）：

> 小工具的上传包不支持直接放 mp3/wav 这类音频文件，我一般用程序现场合成短音效（点一下「叮」、失败「噗」这种），不需要额外文件，也不影响审核。如果想要完整 BGM，我可以用合成器做一小段循环，但听感会比真音乐简单——这个你接受吗？

### 第 4 轮：社交与平台能力

问清要不要这四件事（每件都说明「需要用户点一下才触发」）：

1. **成绩海报**：结算后生成一张 3:4 图，能保存到相册（最推荐，传播全靠它）。
2. **发笔记**：调起发布页带上成绩图（用户自己点发布，不是自动发）。
3. **关注作者**：结算页一个「关注我」按钮（只能关注当前小工具的发布者）。
4. **分享小工具**：拉起分享面板（仅全屏容器可用，半屏/旧版本没有）。

再问一句：**「要不要记历史最佳成绩？」** 需要就说明「存在设备本地，换手机/清缓存会丢」。

### 第 5 轮：范围裁剪

把前面聊出来的东西列成两栏，让用户砍：

> V1 必做（我建议）：
> - 核心玩法 + 失败结算 + 再来一局
> - 成绩海报 + 保存相册
> - 历史最佳
>
> V1 可以砍（砍了不影响上线）：
> - 排行榜（要先有云能力，且审核更久）
> - 多套皮肤 / 关卡编辑器
> - 分享面板（旧版本没有，做了也只能部分人用）
>
> 你想保留哪几个？我建议先上线最小版本，跑通审核再加。

**范围只能减不能加**，用户中途要加功能就写变更单（见 `02-spec-package.md`）。

## 需求卡（聊完立刻写，用户能看见）

写到 `01_需求/00_任务卡.md`，模板：

```markdown
# 任务卡：<工具名>

- 提出人 / 日期：
- 参考对象：（链接 + 是否有复刻意图；无则写「原创」）
- 一句话玩法：
- 目标用户：
- 单局时长：
- 操作方式：
- 结束条件：
- 分数规则：
- 平台能力：海报 / 笔记 / 关注 / 分享 / 存储（勾选）
- 美术方向：
- 音频：合成音效 / 无
- V1 必做：
- V1 不做：
- 已知未知项：（对应 12_风险与未知.md 的编号）
- 决策记录：见 02_方案/01_决策追踪.md
```

## 出口条件（不自查不许进 P2）

- [ ] 能用一句话说清玩法，且用户点头确认过
- [ ] 操作方式、结束条件、分数规则齐全，没有「大概」「可能」
- [ ] 复刻项目：每条规格都有 `VERIFIED`/`PARTIAL` 标记，`UNKNOWN` 全在风险表里
- [ ] V1 必做/不做两栏用户确认过
- [ ] 平台能力勾选完成，且用户知道哪些能力在旧版本没有
- [ ] 音频方案用户确认过「合成音效可以接受」
- [ ] 名字和简介有 3 个候选（不用定稿，P7 再定）

## 反模式（这些做了会被用户嫌烦）

- ❌ 问「你想用什么技术栈 / 框架 / 渲染方式」——这不是用户的事。
- ❌ 一口气甩 15 个问题，用户会跑。
- ❌ 用户说「你定」还继续追问——直接按推荐值定，告诉他你定了什么。
- ❌ 把原版截图当验收基准逐像素比——玩法像就够了，像素级复刻既做不到也没必要。
- ❌ 还没聊玩法就开始生成图标——顺序错了，图标要等玩法和名字定了再做。
- ❌ 遇到不知道的数值自己编一个填进去——标 `UNKNOWN` 或问用户。
